| 백엔드 적합도 | 13 |

- Summary: Oracle 기반 서비스를 MySQL로 무중단 이전하는 과정에서 데이터 동기화, 검증, 트래픽 전환, rollback 판단을 어떻게 다뤘는지에 초점을 둔 운영 사례입니다.
- Why it matters: 운영 중인 서비스의 DB를 바꾸는 일은 단순 스키마 변경이 아니라 쓰기 경로, 읽기 검증, 배포 순서, 장애 대응이 모두 얽힌 백엔드 실무 과제입니다. 랭킹 근거는 Spring backend relevance, JPA persistence topic, Database topic, Infrastructure topic입니다. 지원자가 트랜잭션과 데이터 정합성을 실제 운영 조건에서 이해하는지 확인하기 좋습니다.
- Backend interview angle: Oracle에서 MySQL로 무중단 이전해야 한다면 dual-write, CDC, bulk migration, read verification 중 어떤 순서로 설계하겠습니까? 꼬리 질문: 전환 직후 일부 데이터 불일치가 발견되면 어떤 지표와 로그를 먼저 확인하고 rollback 여부를 어떻게 판단하겠습니까?
- 30-minute study path: 10분: 원문에서 데이터 흐름, 검증 지점, rollback 조건만 표시하며 읽습니다. 10분: `zero-downtime database migration rollback strategy`를 짧게 리서치합니다. 10분: Spring Boot에서 검증할 수 있는 체크리스트 3개를 적습니다. 참고 URL: https://d2.naver.com/helloworld/6512234
- Mini project idea: Spring Boot 주문 API를 H2의 old/new 테이블 두 벌로 구성하고, 쓰기는 양쪽에 반영하되 읽기는 feature flag로 전환하는 미니 마이그레이션을 구현합니다. TODO-STUDENT는 데이터 검증 쿼리와 전환 조건 판단 로직으로 둡니다.

- 30-minute study path: 10분: 원문에서 어떤 endpoint가 운영 판단에 쓰이는지, 어떤 endpoint는 숨겨야 하는지만 표시하며 읽습니다. 10분: `Spring Boot Actuator health groups and endpoint exposure`를 짧게 리서치합니다. 10분: Spring Boot에서 검증할 수 있는 체크리스트 3개를 적습니다. 참고 URL: https://github.com/codecentric/spring-boot-admin
- Mini project idea: 두 개의 Spring Boot 앱과 하나의 admin 역할 앱을 만들고, `/actuator/health` 결과를 수집해 간단한 상태 대시보드 API로 노출합니다. TODO-STUDENT는 DOWN 상태 감지와 알림 이벤트 생성 로직으로 둡니다.
